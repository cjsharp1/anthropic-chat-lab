What it is

The premise

A normal chat window with an activity log beside it. The log shows every request that leaves the machine and every response that comes back — the actual JSON, not a summary — along with what each one cost and why it happened.

You can switch the orchestration pattern, the models, the tools, the system prompt, caching, thinking and effort between messages, and watch the numbers change. It is built for people preparing for the Anthropic certifications, and for anyone who would rather see stop_reason: "tool_use" arrive than read about it.

It runs entirely on one machine. No database, no Docker, no hosting. The only network calls go to the Anthropic API.

The measurement that makes the point

Asked what stop_reason: end_turn means, the Terse system prompt answered in 23 output tokens. Teaching assistant took 589 — 25× the cost for the same fact. The system prompt is the cheapest lever in the app and the easiest to overlook.

The two TypeScript configs

The split is a security boundary, not a build convenience. The server config targets ES2022 with module: NodeNext, strict: true, and types: ["node"]. The client config sets "types": [] — deliberately empty — so server-only globals like process cannot be referenced from browser code even by accident. The API key is never reachable from the frontend half.

Why no framework

The page is the teaching surface. A framework would put its own abstraction between the reader and the JSON on the wire, which is the one thing the app exists to show. The Markdown renderer is hand-written for a related reason: model output renders through textContent, never innerHTML, and a packaged renderer would not guarantee that.

The project was built from a self-contained build plan that sits in the folder it describes. It is one HTML file with its own styling, dark mode, a progress counter, and checkboxes that persist to browser storage. Each step is sized for under 30 minutes and ends with a done-check you can run.

Each step has three parts

What to do, a done check — a literal command plus its expected output, such as npx tsx scripts/check-env.ts printing PASS — sk-ant-a… — and often a gotcha recording a trap hit in practice. The plan tells you that if a step stalls, paste it back to Claude and ask for it to be split into 23a, 23b.

Gotchas worth keeping

  • tsc fails with TS18003 when include matches zero files — create the folders and one throwaway file first.
  • NodeNext needs .js extensions on imports even though the file on disk is .ts.
  • A 401 is often routing, not credentials. The SDK reads ANTHROPIC_BASE_URL, so a company gateway silently intercepts the call.
  • TypeScript does not know process.exit() ends the program, so narrow the key with an early return instead.

Conventions held through the build

What the code enforces on itself

Every file explains itself

Each file opens with a comment saying what it does and why it exists; npm run audit-comments checks none were missed. These record design history rather than restating the code. The tool registry's header explains that an earlier version put the interface in the registry file, creating an import cycle that worked with one tool and threw Cannot access 'currentTime' before initialization with two.

Dependency order as a rule

Tools follow three levels: types.ts imports nothing, definitions/ imports types, registry.ts imports the definitions. A module defining shared types belongs at the bottom of the graph. The frontend holds a matching rule in the other direction — app.ts imports from log.ts, settings.ts and transcript.ts, and nothing imports app.ts.

Security by construction

  • The key is held in server memory, never sent to the browser and never written to disk. An optional git-ignored .env can seed it at startup.
  • The client tsconfig sets "types": [] so server globals cannot be referenced from frontend code.
  • Model output renders with textContent, never innerHTML — including inside the hand-written Markdown renderer.
  • read_file resolves to a canonical absolute path then checks it is still inside the sandbox, the ordering that defeats ../.
  • No authentication, binds to localhost. Not for a network.
